# A-02 · Obligations engine and rule language

## Goal
Deterministic, versioned, human-authored rules mapping graph state to duties, each declaring its jurisdiction and citation.

## Acceptance criteria
- [x] Rules are data, not code, and are reviewable by a non-programmer
- [x] Evaluation is total and deterministic — same graph, same jurisdiction, same duties, always
- [x] Every rule cites an article that resolves in the corpus, checked in CI
- [x] A rule cannot be added without a test case and a citation

## How this is verified
```bash
pnpm test:unit -- rules-engine && pnpm run check:rule-citations
```

- 2026-09-04 17:15 — @gc/rules. The rule language (language.ts) is JSON a person can read: a rule has an id, a title and a summary in the case's languages, a `when` (always, or a condition over named facts joined by all, any and not, with eq, ne, gt, gte, lt, lte, in, contains, exists and empty), an optional `unless`, citations as instrument and ref rows, the finding types that show the duty unmet, and worked examples; the schema refuses a rule without a citation or without an example, and a set with a duplicate id or a file named for another jurisdiction. The fact sheet (facts.ts) derives every fact from the register rows and the company (FACT_NAMES lists the twenty with a sentence each) and leaves out what it cannot derive. The engine (engine.ts) is three-valued: an absent fact is unknown, not false; all/any/not follow; a rule whose condition is unknown, or whose unless might hold, gives an undetermined duty, so evaluation is total and never throws, and the same sheet under the same jurisdiction gives the same duties in the same order (Union set then the country's, by rule id) whatever order the sets arrive in. Three sets: EU (ten rules: the record, information at collection, withdrawable consent, processor contracts, transfer safeguards, cookie consent, security, breach readiness, special categories, legitimate-interest weighing), DK and DE (the complaint route to the authority). scripts/check-rule-citations.ts (pnpm check:rule-citations, in CI) resolves every citation in the corpus as published, runs every example and refuses a rule that reads a fact the sheet never produces; the rules content is also in the citation audit. tests/unit/rules/rules-engine.test.ts: 25 citations resolve, 33 examples pass, every status is worked somewhere. The db-side adapter that reads a case's graph into a sheet and stores duties is A-06's.
