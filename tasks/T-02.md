# T-02 · Golden expectations and the differ

## Goal
Compare produced findings against expected.json with a readable diff, and make updating a golden a deliberate act.

## Acceptance criteria
- [x] Diff output names exactly which finding was missing, extra or changed
- [x] Updating goldens requires an explicit flag and shows what changed
- [x] A silently changed golden is caught in review because the diff is committed

## How this is verified
```bash
pnpm test:integration -- goldens
```

- 2026-09-04 11:05 — every non-hostile fixture carries a golden.json: the full set of findings it raised when last accepted (type, severity, subject), families recorded, sorted by identity. packages/scanner/src/fixtures/golden.ts reads, writes and diffs them; the diff names each finding as missing (in the golden, not raised), extra (raised, not in the golden) or changed (severity or subject), one line each, with a one-line head that counts. tests/integration/goldens.test.ts scans each fixture and fails on any difference with that text, and tells you the deliberate act: pnpm goldens:update (scripts/update-goldens.mjs sets GC_UPDATE_GOLDENS=1), which rewrites the goldens, prints what changed per fixture and keeps artifacts/goldens.txt. The goldens are committed, so a scanner that drifts shows up as a diff next to the change that caused it. The differ has its own unit test; the README says how it works.
