- 2026-09-04 21:20 — The ask lives in exactly one place: the confirmation a fix gets. RecheckReport shows it when a re-check closes the finding, and the case page shows it with the attestation notice; the register, the questions, the timeline and the front page never carry it. The link is the front page with ?ref=<code>, the code twelve hex characters derived from the case number (referral_code on cases, migration 0019, filled for every existing row); the front page puts the code into a hidden field of the scan form, the scan route accepts it only in that shape, the job carries it, and the case the scan opens records it as referred_by. Nothing else moves: no cookie, no third-party request, and the test counts both. The referrer's case page shows how many companies started from the link, as a count, without the ask. The benchmark comes from the canary corpus: the nightly run writes benchmark.json (the date, the number of sites scanned, and how many open findings each had) beside the snapshots and into fixtures/canary, which the workflow commits; the case page reads it (CANARY_BENCHMARK_FILE) and says the share of watched sites with more open findings than this case, the number of sites and the date, and below thirty sites it says how many it is waiting for and gives no percentage. tests/e2e/referral.test.ts: the ask absent everywhere before the fix and present once after; a scan from the link attributed on our side with no tracker and no cookie; the count on the referrer's page; the benchmark with forty sites and withheld with eight.
