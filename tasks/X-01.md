# X-01 · Prototype scaffold and design system

## Goal
A Next.js app with the design tokens, type scale, both themes and the locale switch — deliberately minimal, no infrastructure.

## Acceptance criteria
- [x] Runs with one command from a clean clone; no database, no services, no environment variables
- [x] Deploys as a static build so Frits can click through it on a phone
- [x] Tokens, type scale and severity colours defined once, matching the concept document
- [x] Light and dark both designed, not inverted; severity readable in greyscale
- [x] A visible PROTOTYPE marker on every screen so no screenshot is ever mistaken for a working product

## How this is verified
```bash
node apps/prototype/smoke.mjs
```

## Notes
Keep it boring and small. F-01 later absorbs this app into the workspace without discarding a single component.

## Deviation from the seed plan
The seed assumed a Next.js app with pnpm, Vitest and Playwright. Built instead as a
single-file, zero-dependency app (styles.css + app.js + the fixture, inlined by
build.mjs). Reasons: the prototype is non-functional by definition, so a framework and
a node_modules tree buy nothing; a single file opens from disk and publishes as one
shareable link with no hosting; and what actually ports to F-01 is the token system,
the CSS and the copy, none of which depend on the framework. Verification is
apps/prototype/smoke.mjs — 79 assertions across all ten screens. F-01 should port the
CSS and fixture as-is and rewrite only the render glue.
