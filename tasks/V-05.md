# V-05 · Dive points on every element

## Goal
Any finding, step, quoted article or phrase opens a conversation already scoped to it. Modelled on GDPRchat Zen dive-deeper — see docs/decisions/dive-points.md.

## Acceptance criteria
- [x] A dive from a page seeds turn zero with the fragment, the case as structured fact, and jurisdiction-filtered corpus; after that it is an ordinary conversation and further dives append
- [x] Fragment handling matches GDPRchat: markdown stripped, capped at 300 characters, prefixed with the localised Tell me more about this
- [x] Gating carried over: nothing to expand, and elements that already offer a specific next action, get no dive point
- [x] The fragment is delimited and labelled as quoted data — it often originates from the customer website or a contract
- [x] Retrieval re-runs scoped to the fragment rather than to the whole case
- [x] Every dive is a timeline event, so the case shows what was asked about

## How this is verified
```bash
pnpm test:evals -- dive-points && pnpm test:adversarial -- dive-injection
```

## Notes
The mechanism in GDPRchat is about fifteen lines because the conversation already holds the context. Ours has to build turn zero, and that is the whole task.
