# A-10 · Prompt-injection defences for untrusted content

## Goal
Everything the scanner reads is hostile input. Treat page text, policies and contracts as data, never as instructions.

## Acceptance criteria
- [x] Untrusted content is delimited and labelled as data in every prompt that touches it
- [x] Model outputs that attempt to change scan scope, severity or verdict on instruction from scanned content are rejected
- [x] The adversarial fixture suite includes sites embedding injection attempts in visible text, HTML comments, alt text, CSS content and the policy document itself
- [x] A successful injection anywhere in the suite fails the build

## How this is verified
```bash
pnpm test:adversarial -- injection
```

## Notes
This product reads attacker-controlled text by design. Treat this as a security control, not a prompt-quality nicety.

Output guards run after the schema on every call that could act on an instruction: plan_tasks (task types offered, crawl/registry scope within the site), answer_question (grounded rows and law from what was offered), explain_finding (evidence refs from what was given), prioritise_plan, classify_cookies (observed only), analyse_policy_clauses (elements asked, quotes in the document), draft_message and draft_agent_prompt (no links nobody supplied); a failed guard is retried once with the reason, then ModelOutputError. No output schema carries severity, verdict, scope, jurisdiction, lane or stage. Fixture injection-attempts plants instructions in visible text, an HTML comment, alt text, CSS content and the policy; tests/adversarial/injection.test.ts proves each stays inside a fence and that an obedient model's answer is refused on every guarded call. pnpm test:adversarial is in CI.
