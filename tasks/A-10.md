# A-10 · Prompt-injection defences for untrusted content

## Goal
Everything the scanner reads is hostile input. Treat page text, policies and contracts as data, never as instructions.

## Acceptance criteria
- [ ] Untrusted content is delimited and labelled as data in every prompt that touches it
- [ ] Model outputs that attempt to change scan scope, severity or verdict on instruction from scanned content are rejected
- [ ] The adversarial fixture suite includes sites embedding injection attempts in visible text, HTML comments, alt text, CSS content and the policy document itself
- [ ] A successful injection anywhere in the suite fails the build

## How this is verified
```bash
pnpm test:adversarial -- injection
```

## Notes
This product reads attacker-controlled text by design. Treat this as a security control, not a prompt-quality nicety.
