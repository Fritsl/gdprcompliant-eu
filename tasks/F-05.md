# F-05 · Multi-tenancy isolation, provable

## Goal
Postgres row-level security plus a per-request tenant context, and a test suite that tries hard to break it.

## Acceptance criteria
- [ ] RLS policies on every tenant-scoped table, enabled by default and FORCEd for the app role
- [ ] A query without tenant context returns zero rows rather than all rows
- [ ] Test suite attempts cross-tenant read, write, join and aggregate — all must fail
- [ ] A new table without an RLS policy fails a lint check in CI

## How this is verified
```bash
pnpm test:integration -- tenancy
```

## Notes
This is one of the two things PLAN.md says cannot be retro-fitted. Do it before any feature code.
