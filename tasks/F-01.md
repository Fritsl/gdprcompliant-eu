# F-01 · Monorepo scaffold and toolchain

## Goal
pnpm workspace, TypeScript strict, ESLint, Prettier, Vitest, and a CI workflow that runs on every push.

## Acceptance criteria
- [x] pnpm install works from a clean clone on Linux and Windows
- [x] tsconfig uses strict:true, noUncheckedIndexedAccess:true, and project references across packages
- [x] A deliberately failing test fails CI; removing it makes CI green
- [x] Layout matches PLAN.md §Repo layout exactly — later tasks assume those paths

## How this is verified
```bash
pnpm install && pnpm -r typecheck && pnpm test:unit
```

## Notes
No app code in this task. The only deliverable is that the harness runs.

## What shipped

pnpm workspace, TypeScript 5.9 strict with project references across nine packages,
ESLint 9 flat config, Prettier, Vitest 2 with six named suites, and a CI workflow that
runs on Linux and Windows.

Deviations worth knowing:

- Vitest 2.1 declares suites in `vitest.workspace.ts`, not `test.projects` — that key
  is Vitest 3. The root `vitest.config.ts` keeps the shared reporter and coverage
  settings and each suite extends it.
- Prettier is scoped away from everything that predates this task. Its first run
  reformatted the prototype, the task files and `docs/plan.html`, which is the source of
  a published artifact; all of that was reverted and `.prettierignore` now excludes it.
- The no-article-numbers rule (I-02) is scoped to the packages that will hold detector
  and rule logic rather than applied repo-wide, because task text and tests legitimately
  name articles. Widen it as those packages fill up.
- Coverage thresholds sit at 70 everywhere. F-08 raises findings, rules and remedies
  to 85 once they hold real code.

CI also runs `pnpm proto`, so the prototype's 430 assertions gate every push — the
design specification cannot silently drift from the rules it encodes.
