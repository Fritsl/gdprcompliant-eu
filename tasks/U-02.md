# U-02 · The front door

## Goal
One field, one button, no account — and honest progress while the three passes run.

## Acceptance criteria
- [x] A scan can be started with keyboard only, and the field validates a domain without being precious about format
- [x] Progress streams real stages, never a fake spinner with invented percentages
- [x] Abuse controls: rate limit per source, queue depth cap, and a polite refusal message
- [x] Works on a phone, because half of first visits will be on one

- 2026-09-04 11:20 — The front door is the home page: one field, one button, no account; POST /[locale]/scan normalises the domain however it was typed (scheme, path, capitals, trailing dot), refuses nonsense, rate-limits per hashed source address (5 an hour, GC_SCANS_PER_SOURCE_PER_HOUR), refuses when the queue holds 50 scans (GC_SCAN_QUEUE_CAP, read from pg-boss queue stats), and sends the visitor to /[locale]/scan/[job]. The scan is a pg-boss job (SCAN_JOB in @gc/db) run by the new apps/worker (@gc/worker, pnpm worker:start): it checkpoints the prototype's ten stages with the worker's own marks (done, could not tell, not needed, skipped, no response), opens the case in the target's jurisdiction, records the scan, and hands back the case token. The scan page is server-rendered from the checkpoints and kept live by an event stream that only relays them; no percentage exists anywhere. tests/e2e/front-door.test.ts runs the worker in-process against the fixture estate on a 375px viewport: keyboard-only start, real stages to the case, a polite refusal for a bad address, and the per-source limit in Danish. Not done: the queue-depth refusal is unit-tested through the limiter and depth code paths but not driven through the browser.
